# 楽フェクター 5機能統合版 — NuGet復元対応版

## 最初にすること（5件の project.assets.json エラーへの対応）

このZIPは**外側の展開フォルダを `RakuFector` に統一**しています。ZIPを完全に展開したうえで、Visual Studioを閉じ、最上位の **`REPAIR_AND_BUILD.cmd` をダブルクリック**してください。

このスクリプトは以下を実施します。

1. .NET SDKがあるか確認します。
2. 5プロジェクトの古い `obj` フォルダを削除します（生成物のみ）。
3. NuGetパッケージを復元します。
4. `Debug / x64` で統合ソリューションのビルドを実行します。
5. 失敗した場合は `restore_and_build_log.txt` に詳細を保存します。

処理が `SUCCESS` で終わったら、`楽フェクター.sln` を Visual Studio 2022 で開いてください。構成 `Debug`、プラットフォーム `x64`、スタートアッププロジェクト `楽フェクター` を選択します。

**必要環境:** Windows 10/11、Visual Studio 2022の「.NET デスクトップ開発」ワークロード、および .NET 8 SDK。NuGetパッケージを初めて取得する際にはインターネット接続が必要です。

**重要:** `project.assets.json` は各PC上で NuGet 復元により生成されるファイルのため、ZIPに固定して含めていません。こちらではWindows実機で復元・ビルドを実行できていないため、ビルド成功を保証するものではありません。復元に失敗する場合は、ログに `NU1301` （通信やNuGetソース）、`NU1101`（パッケージ取得失敗）、`NETSDK`（SDK不足）などの原因が表示されます。

以前の版でVisual Studioを開いている場合はそのウィンドウを閉じ、**この修正版の** `.sln` を開き直してください。

# 楽フェクター 5機能統合版 — 音作り + チューナー + コード検出 + ドラム編集 + フットスイッチ

このZIPは、ユーザー提供の次の4つのプロジェクトの**実装部分を統合したWPFソリューション**です。

- `FXForge_HeavyDrive_LowLatency_solution (3).zip` から **音作り**（SD-1/RAT音色、ASIO入力・エフェクト処理・PC/ASIO出力）とアプリ共通部分
- `チューナー機能(ほぼ完成)(1).zip` から **チューナー解析**（FFT/HPS音名・周波数・セント表示）
- `DrumEditor_NET8_Ride修正_Clear拡張版 (2).zip` から **ドラム編集**（13音色、ステップ編集、BPM、MIDI読込/出力、WAV出力、保存、Undo/Redo、拡張編集）
- `ChordDetectionDemo - コピー (2)(1).7z` から **コード検出**（Basic Pitch/ONNXによるコード解析、録音、音声ファイル読込、検出結果のタイムライン表示、再生、音源分離Demucs）

**コード検出は実際の解析コードに置換しました**。この統合版ではフットスイッチもWinForms版からWPFに移植し、操作・割当・JSON保存読込・音作り連携を追加しています（詳細は `FOOTSWITCH_INTEGRATION.md`）。

## Windowsでの開き方

1. ZIPをすべて展開します（ZIPの中から直接開かないでください）。
2. Windowsで Visual Studio 2022 を使い、`楽フェクター.sln` を開きます。
3. Visual Studio Installerで「.NET デスクトップ開発」を導入し、.NET 8 SDK があることを確認します。
4. ソリューション構成を `Debug` / `x64` にし、スタートアッププロジェクトを `楽フェクター` にします。
5. NuGetを復元し、ビルドして起動します。コマンドラインの場合は `build_windows.bat` も利用できます。
6. 音作り・チューナー・コード検出でASIO入力を使う場合は、ヘッダーの⚙からドライバー・入力番号・周波数を設定してください。コード検出画面の「ASIOで録音」を有効にすると**同じ入力ストリーム**を録音します。ドラム編集も同一ウィンドウの左メニューから切り替えます。
7. コード検出の「音声ファイルを開く」からWAV/MP3等を選ぶと、録音なしで解析できます。音源分離は大型のONNXモデルを使用するため負荷があります。

## 統合上の調整

- WPFの起動ウィンドウを`楽フェクター/MainWindow`に一本化しました。別個の`DrumEditor.exe`を起動する方式ではありません。
- ドラムエディタの元の`Window`を`UserControl`に移し替え、**同じウィンドウの内部で全体画面に切り替え**る方式にしました。ドラム画面内の左メニューからも別画面に戻れます。
- ドラム編集固有の色・UIスタイルはドラム画面内に限定し、他の画面のスタイルを上書きしません。
- ドラムの保存確認、MIDI/WAVのダイアログ、音源・操作機能、オーディオ再生、編集状態を保持しています。ウィンドウの閉じ処理は統合側が管理します。
- チューナーには、実際の解析コード`TunerAnalyzer.cs`を組み込みました。音声は共通`CommonAudioInput`から受け取り、FFTは別タスクで行うことでASIO音声コールバックを長く止めないようにしています。
- コード検出の元の独立`MainWindow`を同じウィンドウ内の`ChordPage`に移しました。録音、停止、Basic Pitchの推論、結果表示、ファイル読込、再生、CSV出力、Demucsによる音源分離を保持しています。モデル`nmp.onnx`と`htdemucs_6s.onnx`、ライセンス文書も含めています。
- コード検出専用の`CommonAudioInput`による**二重ASIO接続を削除**しました。音作り・チューナーと共通の入力を購読し、コード検出画面だけの録音を開始・停止します。録音中は共通音声の設定変更およびアプリ終了を停止して、録音ファイルの途中破損を防止します。
- コード検出UIの旧「ダークモード」トグルと重複する画面ナビゲーションを削除し、楽フェクターの既存の画面切り替えと配色に統合しています。
- 音作り側の低遅延モニター、歪みアルゴリズム、音声設定は残しています。
- **音作り・チューナー・コード検出録音の入力**は`CommonAudio`で共通化しています。**ドラムの音源再生**は元のドラムエディタの再生エンジンを保持しており、ASIOモニターへミックスする方式には未変更です（Windowsの再生デバイス側で出力されます）。

## 検査したこと / まだ検査できていないこと

- 検査済み: 全XAMLのXML構文 / XAMLイベントハンドラ名の存在 / ソリューションのプロジェクト参照・モデル同梱 / ASIOの二重起動排除。
- 未検査: Windows上での`dotnet build` / 実際の起動 / UR22Cなどを使ったASIO接続 / MIDI・WAV書き出しを含む実機操作試験。作業環境がLinuxであり、Windows用WPF SDKを利用できないためです。**ビルド成功を保証するものではありません。**
- NuGetパッケージの復元にはネットワークが必要な場合があります。

## ソリューション構造

- `src/楽フェクター`：アプリの起動ウィンドウ、音作り、チューナー、共通設定、その他の画面
- `src/CommonAudio`：ASIO・PC出力対応の共通オーディオライブラリ
- `src/ChordDetection.Core`：コード分類・ノート検出・音楽解析ロジック
- `src/ChordDetection.Infrastructure`：Basic Pitch/ONNX・録音/音源分離（モデルファイルを含む）
- `src/楽フェクター/ChordDetection`：コード検出用ViewModelやダイアログ等
- `src/楽フェクター/Views/ChordPage.xaml`：統合したコード検出画面
- `src/DrumEditor`：移植済みのドラム編集画面、ドラム音源、保存・読み込み・編集機能

> 実行ファイル（exe）の完成品ではなく、Windows/Visual Studioでビルドするための**統合済みソースプロジェクト**です。

## コード検出の操作上の注意

- コード検出画面の「ASIOで録音」を使う場合、まずアプリ右上の ⚙ で共通音声入力を接続してください。コード検出は接続済みのドライ音を録音します。
- ASIOを使わない場合はチェックを外して「詳細設定（開発用）」からWindows録音デバイスを指定できます。
- 基準ピッチの440Hz/442Hzの選択は、移植元の仕様と同じく**表示用のみ**で、Basic Pitch解析の基準は440Hz固定です。
- `.NET 8`、Windows 10/11、Visual Studio 2022 のデスクトップ開発ワークロード、x64でのビルドを想定しています。NuGet復元でONNX Runtime等が導入されます。
- **Windows上でのビルド・実音声を使った検証は未実施**です。コンパイルや動作に問題が出た場合は、Visual Studioの「エラー一覧」と例外メッセージを参照してください。
